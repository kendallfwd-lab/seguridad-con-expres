# Security Lab — instrucciones permanentes
Trabaja sobre este repositorio, no sobre otro. Lee MASTER_PROMPT.md, IMPLEMENTATION_PLAN.md, SECURITY_RULES.md, ACCEPTANCE_CRITERIA.md y TASKS.json antes de editar. El código inicial usa MySQL y NO es la versión final. Migra realmente a PostgreSQL.
Ejecuta cada fase, inspecciona resultados, corrige errores y registra evidencia en docs/EXECUTION_LOG.md. No marques tareas como done sin pruebas. Si una fase está bloqueada, marca blocked y continúa con tareas independientes. No inventes credenciales, resultados, URLs ni pruebas. No borres datos, proyectos o ramas ajenos; no publiques secretos ni contrates servicios sin permiso. Solicita intervención para OAuth, elevación de permisos, selección de proyecto remoto y autorización de despliegue. Lee la documentación vigente antes de ejecutar comandos de Supabase o Vercel. Usa git diff y commits pequeños sin secretos. Mantén frontend sencillo, backend real y verificable. No sustituyas controles por simulaciones. Entrega comandos reproducibles, evidencias y limitaciones.
