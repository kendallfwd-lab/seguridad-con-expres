# Misión de Codex
Actúa como ingeniero Full Stack, DBA, DevOps y especialista en seguridad. Ejecuta el trabajo, no respondas solo con un plan. Inspecciona el repositorio y Windows; instala PostgreSQL y pgAdmin si faltan mediante instalador oficial o winget con ID verificado; conserva instalaciones y datos existentes. Comprueba Node LTS, npm, Git, psql y pg_isready. Docker es opcional para el stack local de Supabase. Si necesitas permisos administrativos, solicita intervención explícita.

Migra mysql2 a pg, usando consultas parametrizadas, RETURNING, TIMESTAMPTZ, constraints e índices. Inspecciona backend/src/server.js, db.js, admin.js, security.js y frontend/src/main.jsx. Adapta todos los endpoints, códigos de errores, IDs, transacciones y frontend; no hagas un reemplazo ciego de signos ?. Separa app.js de server.js para pruebas y serverless. Conserva las rutas existentes. Crea migraciones versionadas con Supabase CLI y un esquema privado app_private. Mantén cuatro tablas existentes y agrega tablas para verificación de correo, recuperación, MFA, códigos de respaldo y límites persistentes. Usa roles separados de migración y ejecución; no uses postgres como rol runtime. Prueba privilegios mínimos.

Mantén autenticación propia Express: Argon2id, JWT 15 minutos, refresh opaco 7 días con SHA-256 y cookie HttpOnly, rotación transaccional y revocación. Completa correo, recuperación, MFA TOTP con AES-GCM y códigos de respaldo. Implementa CSRF, CORS allowlist, Helmet, validación Zod, autorización RBAC y ownership, auditoría, rate limiting persistente por cuenta e IP. No uses localStorage para tokens. La lista inicial de contraseñas comunes es insuficiente: incorpora una fuente de contraseñas comprometidas con privacidad y comportamiento ante fallo documentado. No declares envío de correo si SMTP no está configurado.

Frontend: React + Vite, login, registro, perfil, notas privadas, sesiones, MFA, recuperación y panel admin/auditoría. Mantén inspector HTTP sanitizado con casos 200/201/204/400/401/403/404/429. No expongas hashes ni tokens.

Supabase: verifica documentación y changelog actuales; CLI --help; autentica con cuenta del usuario, identifica organización y proyecto, solicita confirmación antes de crear o modificar recursos remotos. Usa migraciones revisadas, dry-run si disponible, nunca reset remoto. DATABASE_URL solo backend, TLS con CA y verificación, Transaction Pooler para serverless sin prepared statements nombrados, conexión directa o Session Pooler para migraciones. No expongas app_private a Data API ni concedas permisos a anon/authenticated. No presupongas que auth.uid() reconoce JWT propio. Si habilitas RLS, prueba políticas coherentes con identidad Express; cualquier contexto por conexión debe establecerse dentro de una transacción y no filtrarse a otro usuario. Ejecuta revisión de seguridad y prueba consultas.

Producción: Vercel para React y Express si compatible con runtime Node y Argon2id. Prioriza mismo origen. Verifica documentación actual de Vercel, configuración de rutas, variables secretas, TLS y limitadores distribuidos. Usa un host Node alternativo solo con autorización si hay incompatibilidad. No publiques automáticamente sin autorización. Ejecuta tests unitarios, integración con PostgreSQL real y E2E. Usa DB de pruebas separada; smoke tests no destructivos en producción. Entrega evidencia, URL real, esquema, migraciones, README, OpenAPI, colección Postman y diagramas Mermaid/draw.io. Sigue ACCEPTANCE_CRITERIA.md y registra bloqueos en TASKS.json.
